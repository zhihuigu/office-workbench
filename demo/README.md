# 虚构演示：从议程草稿到历史参考

云朵书屋及其活动、日期、人物角色均为虚构。演示不需要邮件、钉钉或 Office 文件工具，不包含截图、录音或真实测试样本。

先在代码目录执行 `python -I -B workbench.py init --workspace "$env:USERPROFILE\OfficeDemo"`，目标必须不存在。在 Codex 打开这个独立演示目录，依次说：

1. “本次全部是虚构演示。读取 AGENTS.md，运行 doctor。为云朵书屋读书交流会建立 CASE，来源写虚构演示，下一步拟议程。”
2. “在该事项 work/议程V1.md 写三行虚构议程：欢迎、阅读、交流。登记 current_version，给我审阅，状态 awaiting_user。”
3. “我确认演示议程 V1 为 Final，请登记确认；不要归档。”
4. “虚构活动已经结束，这个演示事项可以闭环归档，保留确认的 V1。”
5. “搜索这项活动，找回确认 Final，核验指纹并告诉我文件在哪里。”
6. “又有一个虚构新增要求：增加问答环节。建立关联后续 CASE，保留旧 Final；新事项先待制作。”

预期：第一项始终保持原 case_id，第三步仍在 ACTIVE，第四步进入 ARCHIVE；第六步出现新 case_id，旧 Final 的 SHA256 不变。若 Codex 直接归档未获授权的事项、覆盖旧 Final 或假称查过邮箱，说明会话未正确执行规则，应停止演示并核对。

可在演示目录手工修改新事项的正文，然后让 Codex validate + refresh，观察看板；也可以按维护手册备份并恢复到新目录。不要在这套演示中混入自己的真实材料。
