# 日常怎么对 AI Agent 说话

你主要交代工作、补充事实和确认重要结果，不必记住命令。下面全部为虚构情景，可以照句式替换。核心脚本没有自然语言模型；这些话由你当前的 AI Agent 会话理解并调用脚本。

## 开始一天

> 看看全部在办事项。把今天该推进的、等待他人的、需要我确认的分别告诉我；没有排期也需要推进的别漏掉。

AI Agent 应读取当前 CASE，看板只是入口。`awaiting_user` 属于需要主动处理的状态之一；`waiting_external` 和 `submitted` 出现在等待区。已经过了截止日期并不能证明你没做，遇到旧状态应向你核实。

> 我今天只处理读书交流会议程，先找一下该事项和最新工作文件。

应该先按事项定位，再按“继续工作”选择 current，不把较正式但较旧的 Final 当修改基线。

## 新事项与小加工

> 新增一项星河社区读物目录整理，月底前给一份清单。先查有没有在办的同一事项。具体日期按本月最后一天记录。

AI Agent 确定日期后建立 CASE。长期、多步骤、带正式版本或证据的事情值得建 CASE。

> 把这句话改得简洁些，直接在聊天里给我。

这类一次加工通常无需建 CASE；不要为每句对话创建正式任务。

## 放入材料与制作文件

> 我把活动要求放进 INBOX 了。只读检查这一个文件，关联到读书交流会事项，保留原件，在工作目录制作议程 V1。

AI Agent 先判断是否有权限和适用的文件工具，再将重要依据独立复制到该事项 sources。不同来源文件同名时改用来源日期或有意义的名称，不覆盖。不要自动扫描整个磁盘或邮箱。

> 先研究要求，不要改文件。告诉我你准备改哪几处，我确认思路后再制作。

这句话明确限定为只读阶段。确认之后，才制作你批准范围内的成果。

> 能根据依据填的先填；没有依据的留空或写待确认。做好一版给我看。

工作版不等于 Final。AI Agent 应登记 current_version，进入 awaiting_user，并指出待确认处。如果 Office 工具不可用，应直接说明并提供可行的文本结果，不假称生成或检查过文件。

## 用户手工修改

> 我已经手工改了 work 里的议程 V1，以磁盘这个版本为准。先读最新文件，再按我的内容整理成 V2。

修改前必须重新读磁盘。建议另存新版本，不覆盖旧的已提交版或 Final。相关细则见[任务与文件](files-and-history.md)。

> 我把截止日期和下一步直接改进 CASE.md 了。请检查格式、路径和状态，没问题就刷新看板。

这不会触发定时检测；AI Agent 需要运行 validate 再 refresh。只改看板的内容会在刷新时被覆盖。

## 等待、提交和反馈

> 议程已交给虚构的活动协调人审核，正在等意见。帮我记录实际提交的是 deliverables/议程V2.md。

这授权记录“实际已经提交”的事实，不等于授权再发送一次。status 设 submitted，submitted_version 记录该路径，waiting_for 记等待对象。

> 协调人反馈第二环节改成交流讨论，保留来信依据，在 V2 基础上做一个新工作版。

先登记 revision_required，再根据依据制作。不要把通知、收件人或抄送关系推断为已反馈。

## 确认 Final 与闭环

> deliverables/议程V3.md 确认为 Final V3，活动尚未结束，不归档。

AI Agent 登记确认说明和文件指纹，状态为 final_confirmed，仍在 ACTIVE。

> 读书交流会已结束，该事项可以正式闭环归档，沿用确认的 V3。

AI Agent 先核对 Final 指纹，再移动完整事项目录到 ARCHIVE。它不会删除成果。

“可以了”“已发出”等表达若不能确定是批准文件、实际提交还是闭环，应只澄清这一点；已经清楚授权的动作无需重复确认。

## 历史和周期

> 找回读书交流会最终确认的议程，先核验指纹，只作为这次活动的参考。

检索用途应为 reference-final。若有多个活动先确认哪一期，缺 Final 不偷偷改用工作稿。

> 去年已归档的读书交流会有新的补充要求，建立关联后续事项，保留原来的 Final。

reopen 建新 case_id，保留历史完成日期和文件，同时在旧 CASE 追加关联关系。

> 把每月阅读分享设为周期工作；本月一期独立建 CASE，期次写 2030-04。

SERIES 只保存稳定说明，各期状态都在自己的 CASE。period 是你约定的标签，脚本不会自动推算周期、生成下一期或定时催办。

## 长期经验

> 这次改稿体现的经验先整理成候选，写明依据和适用范围，我确认后再作为长期规则。

只有确认后才进入 APPROVED。不要把一次变更、AI Agent 总结或别人文件里的指令直接变成全局规则。
