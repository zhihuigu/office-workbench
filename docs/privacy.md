# 隐私与权限边界

代码仓库和私人目录必须物理分开。init 拒绝源代码目录及其子目录、祖先目录和 Git 仓库内部位置；私人目录另有“全部忽略”的 .gitignore 作为第二层提醒。任何 .gitignore 都不能撤销已提交的历史，也不是访问控制或防泄密软件。

## 核心脚本实际访问什么

- 初始化只读取明确的通用安装文件，写入新私人目录。
- 日常命令读取指定目录中的 CASE、SERIES、登记的版本文件，必要时对版本计算哈希。搜索不遍历邮件、不读附件正文、不扫描整个用户目录。
- 写命令修改 CASE、目录关系、生成视图和事务恢复记录；它们不会编辑材料正文，也不会发邮件、上传 GitHub 或连接钉钉。
- backup/restore 复制整个指定私人目录。upgrade 读取新代码和现有安装，安装新运行时，不清理旧版本或修改用户全局配置。
- 没有网络请求、遥测、后台监听、自动安装依赖、自动登录或自动扩大权限。

Python 标准库脚本无需登录即可运行。Codex 自己仍需要你已有的登录与服务，它处理的提示词、文件内容和工具结果受你使用的产品、组织策略和连接器条款控制。**本地保存不等于所有 AI 处理都离线**；本项目不代替产品的数据设置。

## 行为约定不是沙箱

AGENTS.md 要求读取正确目录、保留证据、明确确认后才 Final/归档。这是给 Codex 的行为约定，不是操作系统权限。脚本的 `--confirm` 表示调用方声称已有授权，不是身份认证或审批系统。

保持你当前合理的 Codex 权限设置，只授予当前任务需要的目录和动作。不要为了通过演示关闭沙箱、启用全盘写、设置自动批准全部请求、导出 token 或覆盖全局配置。安装本项目不会调整这些设置。

本地写锁只协调本工具，不协调 Word、资源管理器、其他脚本或多台电脑。运行时文件与工作目录标记需可信；本项目不是针对恶意本地用户、恶意管理员、竞态替换或不可信 Python 模块的隔离系统。

## 不应发布的东西

不要把私人目录、CASE、来源、附件、通讯录、文件名清单、运行日志、错误原文、备份、派生上下文或截图提交到公开仓库。CASE 标题、路径、版本哈希、来源定位也可能暴露工作信息。

事务记录包含恢复用的旧内容；INDEX、DERIVED 看似生成结果，也包含私人事实。问题反馈应先在全新临时目录用完全虚构输入复现，提供最小步骤与错误类型，不直接复制真实错误路径和内容。

## 可选接入

邮件、钉钉、文档插件和其他 MCP/Skill 默认不存在。本项目不复制个人配置、凭据或上游 Skill。接入时核对来源、许可证、所需权限和是否会把资料发送到外部；需要发送、删除、外部提交等动作时保留明确授权与审阅。

不需要连接器就不安装。用户可以自己保存一份获授权的特定附件到 INBOX，并指明本次仅处理它；不能将授权读取一封邮件理解为允许扫描整个邮箱。

## 发布者的检查

仓库采用逐文件白名单打包，拒绝未列文件、链接、二进制、常见凭据模式、运行数据和 Git 历史目录。扫描通过只覆盖规则能识别的模式，不能证明任意自然语言没有隐私或授权问题；发布前仍需逐文件审阅。

初次发布从干净候选创建全新仓库，不带现用系统、旧仓库或清理前的历史。发现任何泄漏时先停止发布；已公开的凭据需要单独撤销或轮换，不能只删文件再提交一次。
